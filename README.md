# CT Ticket System

A ticket management application built as part of my transition from front-end development into full-stack and web platform engineering.

The project is being developed incrementally, beginning with core JavaScript business logic and evolving into a production-ready full-stack application.

## Current Version

### v0.7 — React + Node.js / Express API

The application now uses a client/server architecture with a React and TypeScript frontend connected to a Node.js and Express REST API.

Ticket data is currently stored in memory on the Express server. The next milestone will replace the in-memory data layer with PostgreSQL for persistent storage.

## Architecture

The application currently follows a client/server architecture:

```text
React + TypeScript
       |
       | HTTP / JSON
       | Fetch API
       v
Node.js + Express
       |
       | Server-side validation
       | CRUD operations
       v
In-memory ticket data
       |
       | Next: v0.8
       v
PostgreSQL
```

The Express API is the source of truth for ticket creation, updates, and deletion. The React frontend updates its local state after receiving successful responses from the API.

## REST API

Current ticket endpoints:

```text
GET     /api/tickets
GET     /api/tickets/:id
POST    /api/tickets
PATCH   /api/tickets/:id
DELETE  /api/tickets/:id
```

The API includes server-side validation and uses HTTP status codes including:

* `200 OK`
* `201 Created`
* `400 Bad Request`
* `404 Not Found`

Ticket IDs are generated by the server rather than the React frontend.

## Automated Testing

The project uses Vitest for automated unit testing.

Run tests in watch mode:


Run the test suite once:

```bash
npm test -- --run
```

```bash
npx tsc --noEmit
```

Each version introduces a new engineering layer while retaining and building upon concepts implemented in previous versions.
